# Requirements: AI 工坊平台

**Defined:** 2026-04-24

**Last reviewed:** 2026-07-29

**Core Value:** 让真实客户需求与可复用技术能力双向透明，并通过明确责任、分级审核和证据留痕，形成可信的关联和决策。

## v1 信息汇总 MVP

### 项目 / 能力管理

- [x] **PROJ-01**：创建预研项目/能力（名称、描述、负责人、标签、状态）
- [x] **PROJ-02**：编辑预研项目/能力信息
- [x] **PROJ-03**：查看能力列表及当前状态
- [x] **PROJ-04**：在详情页查看能力信息及关联需求

### 需求管理

- [x] **REQM-01**：销售/咨询提交客户需求（标题、描述、客户、联系人、紧急度、标签）
- [x] **REQM-02**：查看需求列表及状态
- [x] **REQM-03**：在详情页查看需求、客户信息和关联能力

### 需求—能力匹配

- [x] **MATCH-01**：人工建立需求与能力关联
- [x] **MATCH-02**：为关联标注完全覆盖、部分覆盖或不覆盖
- [x] **MATCH-03**：查看整体匹配覆盖率
- [x] **MATCH-04**：按行业/业务线查看匹配覆盖率

### 标签、协作与总览

- [x] **TAG-01**：管理员定义行业/业务线标签
- [x] **TAG-02**：按标签筛选需求和能力
- [x] **COLLAB-01**：对需求或能力添加文字评论
- [x] **COLLAB-02**：查看完整评论历史
- [x] **DASH-01**：查看能力、需求、关联和覆盖率等关键统计
- [x] **DASH-02**：按行业/业务线切换总览视图

## v2.0 平台化

### 身份与角色工作台

- [x] **ROLE-01**：进入平台先选择销售/咨询、研发或管理员身份
- [x] **ROLE-02**：身份和姓名/团队仅保存在当前浏览器，可随时切换
- [x] **ROLE-03**：销售以需求池为主，可新建/编辑需求，能力池只读
- [x] **ROLE-04**：研发以能力池为主，可维护能力并处理技术确认，需求池只读
- [x] **ROLE-05**：管理员以审核治理为主，可访问总览、审核、关联和知识管理
- [x] **ROLE-06**：管理员不显示新建需求/能力入口，避免代替业务和研发承担数据责任
- [x] **ROLE-07**：操作按角色显隐；明确这只是界面级能力分流，不是安全权限边界

### 角色视角

- [x] **VIEW-01**：销售工作台突出新建需求、我的需求状态和匹配进展
- [x] **VIEW-02**：研发工作台突出能力维护、待评估需求和技术确认
- [x] **VIEW-03**：管理员工作台突出审核队列、全局统计和关联治理
- [x] **VIEW-04**：角色入口使用施耐德品牌视觉，主内容在画面中居中呈现

### 需求数据质量与审核

- [x] **REVIEW-01**：需求状态机覆盖草稿、待审核、已受理、匹配中、已匹配和已搁置
- [x] **REVIEW-02**：管理员可以为需求指派明确的审核责任人
- [x] **REVIEW-03**：被指派的审核人才能执行对应审核
- [x] **REVIEW-04**：提交人不能审核自己提交的需求
- [x] **REVIEW-05**：需求详情展示提交人、审核责任人、实际审核人和审核意见
- [x] **REVIEW-06**：审核事件记录操作人、时间、意见、原状态和新状态
- [x] **REVIEW-07**：通用编辑接口不能绕过需求状态机
- [x] **DATA-01**：新需求必须记录提交人并具有有效业务描述
- [x] **DATA-02**：拒绝空白、过短或明显占位的描述
- [x] **DATA-03**：历史数据缺少审计字段时如实提示，不补造信息

### 关联治理

- [x] **GOV-01**：人工或 AI 创建的关联先进入待技术确认
- [x] **GOV-02**：研发完成技术确认后，关联进入管理员终审
- [x] **GOV-03**：只有终审通过的关联才成为正式匹配
- [x] **GOV-04**：创建关联的人不能审核自己创建的关联
- [x] **GOV-05**：技术确认人不能同时执行最终审核
- [x] **GOV-06**：驳回必须填写原因
- [x] **GOV-07**：关联详情保留创建人、审核人、时间、结论及 AI 依据

### AI 辅助

- [x] **AI-01**：自然语言生成需求结构化草稿
- [x] **AI-02**：自然语言生成能力结构化草稿
- [x] **AI-03**：识别 PNG、JPG/JPEG、WEBP 图片并生成可编辑文本
- [x] **AI-04**：对需求与能力池进行候选分析
- [x] **AI-05**：候选结果包含评分、覆盖结论、理由、缺口和维度评分
- [x] **AI-06**：AI 结果只能作为建议，必须经过人工审核才能生效

### Chatbot 与知识库

- [x] **CHAT-01**：任意已进入工作台的页面都可以唤起全局助手
- [x] **CHAT-02**：助手基于 RAG + Qwen 多轮回答并展示引用来源
- [x] **CHAT-03**：销售可把对话转换为需求草稿并带入表单
- [x] **KB-01**：导入 TXT、Markdown、CSV 文档
- [x] **KB-02**：支持检索、来源过滤、引用片段和知识问答
- [x] **KB-03**：管理员可查看、删除文档并重建索引
- [x] **KB-04**：需求和能力数据自动同步到检索知识
- [x] **KB-05**：空知识库或检索失败时给出可理解的降级提示

### 生产可运行性

- [x] **OPS-01**：后端由 systemd 托管，监听本机回环地址
- [x] **OPS-02**：Nginx 提供前端和 API 的统一访问入口
- [x] **OPS-03**：生产 AI 配置独立保存在 `/etc/action-learning.env`
- [x] **OPS-04**：部署过程保留生产数据库、环境配置和共享 Nginx 站点
- [x] **OPS-05**：应用已部署到阿里云并通过健康检查

## v2.1 试运行闭环

- [x] **PILOT-01**：按销售、研发、管理员身份返回个人待办
- [x] **PILOT-02**：待办显示 SLA、剩余时间、12 小时内到期和逾期
- [x] **PILOT-03**：管理员看到待指派、待审核、待关联和待终审
- [x] **PILOT-04**：研发看到待技术确认，销售看到待补充需求
- [x] **QUALITY-01**：需求和能力使用明确规则计算数据质量分
- [x] **QUALITY-02**：低于 80 分的数据进入待改进清单
- [x] **QUALITY-03**：清单列出缺失字段并支持进入详情
- [x] **EVAL-01**：使用人工审核结论标记 AI 候选是否采纳
- [x] **EVAL-02**：统计 AI 候选数量、已评测数量、采纳率和平均分
- [x] **EVAL-03**：展示最近 20 组评测样例和高频能力缺口
- [x] **METRIC-01**：统计审核人覆盖率和候选能力覆盖率
- [x] **METRIC-02**：统计平均需求审核周期和平均匹配确认周期
- [x] **METRIC-03**：管理员总览集中展示试运行指标

## 最终不做

- [ ] **CANCEL-01**：企业 SSO、通讯录和后端 RBAC
- [ ] **CANCEL-02**：邮件、Teams、WebSocket 等实时通知
- [ ] **CANCEL-03**：PostgreSQL、Alembic 和大规模基础设施改造
- [ ] **CANCEL-04**：CRM、Jira/Confluence 等企业系统集成
- [ ] **CANCEL-05**：移动端、复杂 BI 和新业务模块

以上项目依据 2026-07-29 决策取消，不进入后续版本。

## 当前明确不做

| Feature | Reason |
|---------|--------|
| AI 自动批准正式匹配 | 模型输出必须由技术和管理责任人确认 |
| 移动端原生 App | 当前以内部 Web 试点为主 |
| 实时多人编辑 | 业务协作以状态和评论为主，暂不需要文档式协同 |
| 外部客户账号/公开注册 | 当前面向内部团队，且尚未接入正式身份系统 |
| 大规模 BI/数据仓库 | 先验证需求—能力治理流程和业务采用度 |
