# AI 工坊平台

## What This Is

AI 工坊是连接客户需求与技术能力的协同治理平台。销售/咨询提交和跟踪客户需求，研发维护能力并进行技术确认，管理员负责需求审核人指派、关联编排、最终审核和知识治理。平台把需求、能力、关联、审核、评论和知识文档统一到可查看、可检索、可追溯的流程中。

当前代码与生产版本均为 v2.1 最终功能版；生产入口为 <http://8.152.171.142/>。

## Core Value

让真实客户需求与可复用技术能力双向透明，并通过明确责任、分级审核和证据留痕，把“看得见”升级为“可信地关联和决策”。

## Context

- 起源：2025 年西安培训行动学习课题
- 业务角色：销售、咨询、研发、技术支持、解决方案工程师
- 当前角色模型：销售/咨询、研发、管理员
- 当前规模：小规模内部试点，手动录入为主
- 技术栈：FastAPI + SQLModel + SQLite；React + Vite + Ant Design
- AI/RAG：Qwen OpenAI-compatible API + Qdrant Client/FastEmbed
- 生产环境：阿里云 `aliyun-home-tunnel`，部署目录 `/opt/action_learning`

## Constraints

- **Identity**：浏览器身份选择不是认证，不能作为安全边界
- **AI**：AI 结果必须由人工审核，不能自动成为正式业务结论
- **Data**：历史记录可能缺少提交人等字段，必须如实提示
- **Database**：SQLite 适合 MVP，不适合高并发和复杂迁移
- **Operations**：部署不得覆盖生产数据库和 `/etc/action-learning.env`
- **Team**：行动学习小组不是专职产品研发团队，优先保持流程清晰和运维轻量

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| 从“全员同屏”演进为角色工作台 | 信息透明不等于操作无边界，需要突出各角色职责 | 销售→需求、研发→能力、管理员→审核治理 |
| 管理员不新建需求或能力 | 防止管理者代替业务/技术承担数据责任 | 管理员聚焦指派、关联、终审和知识管理 |
| 需求审核人显式指派 | 解决“谁审核、谁负责”不清晰 | 详情展示提交人、责任人、实际审核人和意见 |
| 关联采用两级审核 | 技术可行性和管理决策属于不同责任 | 研发技术确认，管理员最终审核 |
| 强制职责分离 | 降低自评自批和利益冲突 | 创建人不能自审，技术确认人不能终审 |
| AI 只做辅助 | 模型可能误判或缺少上下文 | 推荐、结构化、问答均保留人工确认 |
| 历史数据不补造 | 业务可信度优先 | 缺失信息以“历史记录未保存”说明 |
| SQLite 零运维 | 适配当前小规模试点 | 作为最终试点存储，不再规划数据库迁移 |
| 同域 Nginx + systemd | 简化访问和运行维护 | 已在阿里云完成部署 |
| v2.1 作为最终功能范围 | 行动学习课题以可试运行闭环为终点，避免继续企业化扩张 | v2.2/v2.3 取消，只保留缺陷修复与数据试运行 |

## Success Signals

真实试运行阶段不再增加功能，只采集：

- 需求从提交到完成审核的平均时间；
- 有明确审核责任人的需求占比；
- 需求获得至少一个候选能力的比例；
- AI 候选被技术确认/终审通过的比例；
- 重复能力或重复需求的识别数量；
- 知识检索减少人工询问的次数；
- 未覆盖需求所代表的重点能力缺口。
